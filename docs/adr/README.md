# Architecture Decision Records

Create an ADR for a durable technical or operational decision that materially
changes the showcase: architecture, authentication, hosting, deployment,
database, observability, or a supported environment.

Use `NNNN-short-title.md` and include:

1. **Context** — decision trigger and constraints.
2. **Decision** — what was chosen and by whom.
3. **Consequences** — benefits, trade-offs, and follow-up work.
4. **Status** — proposed, accepted, superseded, or deprecated.
5. **Links** — relevant issue, pull request, and validation evidence.

Do not create ADRs for routine implementation details. Link accepted ADRs from
the current-state documents where they affect contributors or operations.
